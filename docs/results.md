# 实验结果

我围绕构建顺序、图后处理、查询策略和实现层优化做了消融实验，记录构建时间、查询时延、Recall@10 和平均距离计算次数。下面是 [课程报告](report.pdf) 中的实验结果。

## 消融实验

我在更新前的 GloVe 数据集上进行本地对照，每次调整一个模块，观察它对构建和查询的影响。各项比较中的 baseline 配置相同，结果汇总如下：

| 配置 | 构建时间 / s | 平均查询 / ms | 中位数查询 / ms | Recall@10 | 平均距离计算次数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 424.1 | 0.758759 | 0.404159 | 0.993 | 13202.77 |
| lid_added | 458.369 | 0.770949 | 0.405591 | 0.995 | 12991.17 |
| no_post_process | 275.763 | 0.758213 | 0.407492 | 0.994 | 12970.31 |
| no_gamma_early_stop | 424.108 | 1.24146 | 0.562775 | 0.994 | 20611.65 |
| cand_always_enqueue | 423.097 | 1.07849 | 0.562775 | 0.993 | 13201.37 |
| float_distance | 538.806 | 1.05907 | 0.57018 | 0.995 | 13197.39 |
| serial_build | 1673.7 | 0.765464 | 0.402186 | 0.993 | 13201.29 |
| no_prefetch | 410.667 | 0.930724 | 0.498464 | 0.993 | 13195.34 |

### LID 插入顺序

加入 LID 重排后，我测得 Recall@10 从 99.3% 提高到 99.5%，平均距离计算次数减少约 1.6%。代价是构建时间从 424.1 s 增至 458.369 s，平均查询时延从 0.758759 ms 增至 0.770949 ms。这项调整的收益主要体现在召回率和搜索扩展规模上。

### 查询早停与候选入队

关闭 gamma 早停后，平均查询时延从 0.758759 ms 增至 1.24146 ms，平均距离计算次数也从 13202.77 增至 20611.65。相较之下，保留早停的 baseline 时延低约 38.9%，距离计算次数少约 35.9%，两者的 Recall@10 分别为 99.3% 和 99.4%。

只保留早停、取消候选入队阈值时，平均查询时延为 1.07849 ms。因此，我在最终实现中同时使用早停和候选入队限制。

### 并行构建、量化与预取

串行建图耗时为 1673.7 s，并行 baseline 为 424.1 s，约有 3.95 倍的构建速度差异，而查询时延和召回率接近。对我来说，并行化主要改善了离线建图效率。

改用 float 距离后，平均查询时延上升到 1.05907 ms；关闭预取后，上升到 0.930724 ms。这两组的距离计算次数与 baseline 接近，反映出单次距离计算和访存开销对查询时间的影响。

### 图后处理

这组对照中，关闭后处理后，构建时间从 424.1 s 降至 275.763 s，Recall@10 从 99.3% 到 99.4%，平均查询时延基本持平。我在最终版本中保留了反向边注入与剪枝，并结合 `M0`、`efConstruction` 和 `gamma` 进行调参。

## 最终版本

完成调参后，我分别在本地更新前、后的 GloVe 数据集上测试了相同代码，并提交到课程测评机：

| 环境和数据版本 | Recall@10 | 平均查询 / ms | 平均距离计算次数 |
| --- | ---: | ---: | ---: |
| 本地，更新前 GloVe | 0.996 | 0.718538 | 约 12970 |
| 本地，更新后 GloVe | 0.996 | 0.800284 | 14362.490 |
| 课程测评机 | 0.9891 | 1.0577 | — |

更新数据集后，本地 Recall@10 保持在 99.6%，平均距离计算次数从约 12970 增至 14362.490，查询时延从 0.718538 ms 增至 0.800284 ms。课程测评机上的 Recall@10 为 98.91%，平均查询时延为 1.0577 ms。
